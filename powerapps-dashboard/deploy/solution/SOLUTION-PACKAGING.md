# Percy — Dataverse Solution Packaging (TEST / fallback)

> **Why this branch exists.** This is a **test** of packaging Percy (the Copilot Studio agent +
> all 9 flows) as a **Dataverse solution** so it can be exported from one environment and imported
> into another as one unit. It lives on its **own branch** so the build-by-hand path on
> `claude/percy-production-plan-7r06vr` stays our fallback if the solution route doesn't work in
> your tenant.

This kit is **self-contained for the Copilot Studio agent build** — the agent instructions, topics,
and the flow/tool manifest are cloned in here ([`agent/`](agent/) and [`flows-manifest.md`](flows-manifest.md))
so you don't have to cross-reference while building inside a solution.

## 🟨 Limitations — read before you start

> [!CAUTION]
> These determine whether the solution route is even viable for you. If any is a hard blocker,
> fall back to the build-by-hand branch.

- 🟨 **Dataverse required (both ends).** The **source** environment (where you build/export) and the
  **target** (where you import) must both be **Dataverse-enabled**. Personal/"My flows"-only
  environments can't hold solutions.
- 🟨 **Your current environment blocks import.** You told us flows can't be imported here — solution
  import pulls flows in too, so the **same admin/DLP policy will likely reject a solution import on
  this environment**. This route is for a **target environment that permits solution import**.
- 🟨 **You can't hand-author the zip.** A valid solution zip (`solution.xml`, `customizations.xml`,
  the agent's bot component, connection-reference wiring) is generated by the platform. The
  supported flow is **build the components inside a solution in the maker portal → Export**. This
  guide is "**build the solution**", not "here's a zip to import".
- 🟨 **SharePoint list is NOT in the solution.** `PercyConversations` is a SharePoint list, not a
  Dataverse table — provision it separately (you already have it). The solution carries the **agent
  + flows** only.
- 🟨 **Power BI dataset/workspace are NOT in the solution.** They're referenced by **environment
  variable** (the ids differ per environment), not packaged.
- 🟨 **Connections don't export — only connection *references* do.** On import you **bind/create the
  actual connections** (SharePoint, Power BI, Copilot Studio).
- 🟨 **Licensing is unchanged.** Copilot Studio and the Power BI connector still need their licences
  in the target — packaging doesn't grant entitlement.
- 🟨 **Agent export caveats.** Topics travel with a solution-aware agent, but **knowledge sources,
  some channel/security settings, and authentication may not export** — re-check them after import.

## Prerequisites

- 🟦 A **Dataverse environment** you can build in, with the maker portal (make.powerautomate.com /
  copilotstudio.microsoft.com).
- 🟥 The **Power BI workspace id** and **semantic model (dataset) id** (for environment variables).
- 🟥 The **SharePoint site URL** and **list name** (`PercyConversations`).
- 🟦 *(Optional, for source control)* **Power Platform CLI** (`pac`): `dotnet tool install --global Microsoft.PowerPlatform.CLI`.

## Step 1 — Publisher + Solution

1. Maker portal → **Solutions → New solution** (or **Publishers → New** first).
2. 🟥 **Publisher display name** + 🟥 **prefix** (e.g. `percy`). The prefix namespaces everything.
3. 🟥 **Solution name** (e.g. `Percy1PctClub`), 🟦 pick the publisher, **Create**.

> [!TIP]
> Build **everything below inside this solution** (or "Add existing" to pull components in). A
> component built in the *default* solution won't export cleanly.

## Step 2 — Environment Variables (so nothing is hardcoded)

In the solution → **New → More → Environment variable**. Create these (Data type **Text**); set a
**Default Value** for your dev env, and leave **Current Value** to be set per-environment on import.

| Variable (🟩 name) | 🟥 Default value (yours) | Used by |
|---|---|---|
| `percy_WorkspaceId` | 🟥 *Power BI workspace id* | every tool flow (Power BI action) |
| `percy_DatasetId` | 🟥 *semantic model id* | every tool flow |
| `percy_SiteUrl` | 🟥 *SharePoint site URL* | orchestrator |
| `percy_ListName` | 🟩 `PercyConversations` | orchestrator |
| `percy_OpePrefix` *(optional)* | 🟩 `OPE-` | OPE normalisation, if used |

> In each flow, reference these instead of typing ids: in the Power BI action's **Workspace** /
> **Dataset** fields, 🟦 pick **Environment variable** from dynamic content (or the env-variable
> value). This is what makes the solution portable.

## Step 3 — Connection References

In the solution → **New → More → Connection reference**. Create one per connector so flows bind to a
reference (re-pointed on import) instead of a hardcoded connection.

| Connection reference (🟩 name) | 🟦 Connector | 🟦 Dev connection |
|---|---|---|
| `percy_sp` | SharePoint | pick/create a SharePoint connection |
| `percy_pbi` | Power BI | 🟥 the **signed-in shared account** (workspace read + dataset **Build**) |
| `percy_copilot` | Microsoft Copilot Studio | the agent's connection |

## Step 4 — Build the 9 flows **inside the solution**

Build each from the manifest in [`flows-manifest.md`](flows-manifest.md) (which mirrors the
build-by-hand steps), but with two solution differences:

- 🟦 In every flow, set connections via the **connection references** from Step 3 (not direct
  connections).
- 🟦 In the Power BI action + SharePoint actions, use the **environment variables** from Step 2 for
  workspace/dataset/site/list.

Flows: `Percy-Orchestrator` + the 8 tools (`Locate`, `CompleteCare`, `CAP`, `IBExpand`,
`CustomerCentricity`, `IPGreenLake`, `Accreditation`, `Summary`). 🟩 DAX bodies and per-flow
specifics are in [`flows-manifest.md`](flows-manifest.md) and `../flows/dax-templates.md`.

## Step 5 — Build the Copilot Studio agent **inside the solution**

1. 🟦 In Copilot Studio, create the **Percy** agent **in the same Dataverse environment/solution**
   (or add the existing agent: Solutions → your solution → **Add existing → Chatbot/Agent**).
2. 🟩 Paste the **Overview → Instructions** from [`agent/percy-instructions.md`](agent/percy-instructions.md)
   (append the §9 rules). 🟦 (pasting is the manual action; the text is provided.)
3. 🟦 Add the **8 tool flows** as **actions**, with the 🟩 descriptions from
   [`agent/topics.md`](agent/topics.md) / build pack §15.2.
4. 🟦 Add the **topics** from [`agent/topics.md`](agent/topics.md) (or rely on generative
   orchestration). 🟦 Generative orchestration **on**; 🟦 web/general knowledge **off**.
5. 🟦 **Publish** the agent.

> [!IMPORTANT]
> Make sure the agent, its tool-action flows, and the connection references are **all in the one
> solution** before exporting — otherwise the export is missing dependencies and import fails.

## Step 6 — Export

1. Solutions → select `Percy1PctClub` → **Export solution**.
2. 🟦 Choose **Unmanaged** (dev / source control) or **Managed** (prod / locked). 🟨 *Decision:*
   managed for a real target, unmanaged if you'll keep editing.
3. Download the **.zip**. (This is the artifact you import elsewhere.)

## Step 7 — Import into the target environment

1. 🟨 Confirm the **target has Dataverse and allows solution import** (Limitations).
2. Target → **Solutions → Import solution** → upload the .zip.
3. 🟦 **Bind connection references** — for `percy_sp`, `percy_pbi`, `percy_copilot`, 🟦 pick or
   🟥 create a connection in the target (the Power BI one = 🟥 the target's shared account).
4. 🟥 **Set environment variable Current Values** — `percy_WorkspaceId`, `percy_DatasetId`,
   `percy_SiteUrl` for the target (these differ per environment).
5. **Import**. Then 🟦 **publish** the agent in the target and 🟦 confirm the flows are **On**.
6. 🟨 Re-check agent **knowledge/auth/channel** settings (may not have exported).

## Step 8 — Source control (optional, recommended)

```bash
# unpack the exported solution zip into reviewable source
pac solution unpack --zipfile ./Percy1PctClub.zip --folder ./solution-src --processCanvasApps
# ...commit ./solution-src... then later repack:
pac solution pack --zipfile ./Percy1PctClub.zip --folder ./solution-src
```
🟥 paths/zip names are yours; 🟩 the commands are provided.
